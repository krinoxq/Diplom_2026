Принято решение держать машинное обучение **вспомогательным блоком, а не ядром работы**. Критерий: выкинь модель — работа развалится или нет? Если основа в методике расчёта риска, а модель лишь проставляет недостающую оценку или ранжирует, то на защите спрашивают «откуда взял число», а не «докажи, что модель лучше правил». Слово «интеллектуальная» в теме закрывается обычным ML на табличных данных; нейросети не нужны никому из четверых, для сотен-тысяч строк ансамбли (случайный лес, градиентный бустинг) работают лучше, и это можно обосновать литературой.

Откуда данные:
- **Перушкин** — выгрузка NVD: десятки тысяч CVE, где вектор и итоговый балл уже проставлены. Учимся на них, переносим оценку на конфигурационные недостатки без CVE. Самая красивая схема из четырёх
- **Ширинкин** — реальные workflow-файлы с публичного GitHub через API. Даже без модели даёт готовый раздел: фактическая статистика по реальным проектам
- **Полыга** — манифесты из публичных Helm-чартов и Artifact Hub плюс генерация своих
- **Ковалев** — синтетический каталог учётных записей (реальный нельзя: персданные), задача без учителя, разметки нет вовсе

**Главный риск на защите — утечка целевой переменной:** разметили данные правилами CIS, обучили на тех же признаках, модель выучила правила, точность 0.99, а ценности ноль. Это первый вопрос, который задаст комиссия, и главный вопрос к консультанту.

Консультант — «дядька Серёга skynet» с работы пользователя, спец по нейросетям. Лист «ML — как делать» в файле матрицы содержит готовые вопросы к нему; идти с постановкой «таблица на N строк и 20 признаков, надо предсказать класс, данных мало», а не с «помоги с дипломом». Нейросети и LLM у него не просить — не тот случай.

Упрощения, внесённые в формулировки матрицы ради выполнимости: «переоценка по событиям изменения конфигурации» → «пересчёт при смене снимка» (не нужен watcher); «граф достижимости» → «типовые сценарии»; «восстановление оценок критичности» → «классификация, обученная на размеченном множестве». Объём по-честному: 60 % времени уходит на сбор и разметку данных, само обучение — 20-30 строк кода и один вечер.

**В НИР кода нет вообще** — первая глава это модель объекта, база знаний, дерево угроз, риск-ландшафт и постановка задач. Всё программирование относится к главам 2-4, то есть к следующему году.

**Why:** ребята в ML не разбираются и боятся этой части; без зафиксированного решения разговор каждый раз скатывается к «может, нейросеть».

**How to apply:** при любом вопросе про ML в этих дипломах сначала проверять, не превращается ли модель в ядро работы, и напоминать про утечку целевой переменной. Матрица и её структура — [[goal-matrix-4-themes]].

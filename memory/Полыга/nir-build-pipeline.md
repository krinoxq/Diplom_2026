Учебные документы собираются генератором, а не правятся руками в Word. Исходники — в `НИР-Полыга/сборка/` (копия рядом с документом на рабочем столе):

- `gen_nir2.py` — сборка .docx: берёт абзацы из черновика ВКР (`Пример\Main\... — Введение.docx` и `— Глава 1.docx`), применяет правки по списку `EDITS`, добавляет новые разделы и оформляет всё по [[vgtu-formatting-rules]];
- `nir_content.py` — тексты разделов, которых не было в черновике; `refs.py` — источники в виде `ключ → библиографическое описание`;
- `figures.py` — схемы: рисуются как SVG и рендерятся в PNG через `chrome --headless --screenshot --window-size=W,H`.

**Ссылки на литературу.** В текстах ставятся маркеры `{{ключ}}` (до трёх ключей в одном), генератор нумерует их по первому появлению и собирает список литературы в этом же порядке — требование правил ВГТУ выполняется автоматически, вручную номера не трогать.

**Кегль на схемах.** Размер шрифта в документе = `F_px * (ширина_рисунка_см / 2.54 * 72) / W_px`. Для читаемости при печати держим ≥ 12 пт: при холсте 1500 px и вставке шириной 17 см это шрифт 38–40 px. `figures.py` печатает получившийся кегль при каждой генерации.

**Замеры делает сам Word через COM** (PowerShell, скрипт обязательно в UTF-8 **с BOM**, иначе PowerShell 5.1 ломает кириллицу в пути):

- `pages_bom.ps1` — номера страниц всех абзацев в `txt/pages.tsv` (генератор берёт их для содержания) и экспорт PDF;
- `tables_bom.ps1` — какие таблицы разрываются между страницами и на какой строке; результат кладётся в `txt/splits.tsv`, где `0` означает «перенести таблицу целиком на следующую страницу», а число — строку разбиения с надписью «Продолжение таблицы N»;
- `toc_update_bom.ps1` — обновляет поле TOC, настраивает стили `оглавление 1–3` (обращаться к ним надо по индексам −20, −21, −22: по именам `toc 1` в русском Word не находятся) и сохраняет docx и PDF.

Порядок: генерация → замер → повторная генерация (номера страниц и разрывы стабилизируются за 2–3 прохода) → обновление оглавления. Для проверки вёрстки страницы PDF рендерятся в PNG через `pymupdf` (`pip install pymupdf`), poppler и LibreOffice на машине нет.

**Автор документа** меняется без перезаписи содержимого: пересобрать zip, подменив только `docProps/core.xml` (`dc:creator`, `cp:lastModifiedBy`, очистить `dc:description` — там остаётся «generated by python-docx»).

**Редактор блок-схем** `programforyou.ru/block-diagram-redactor` принимает `.json` вида `{"blocks": [...], "arrows": [...], "x0": 0, "y0": 0}`. У блока `x, y` — **центр**, сетка 10 px, тип `"Блок"` или `"Текст"` (плюс «Условие», «Начало / конец» и др.), перенос строк через `\n`. У стрелки индексы блоков и коннекторов (**0 — верх, 1 — право, 2 — низ, 3 — лево**), в `nodes` достаточно двух узлов — путь редактор достроит сам. Проверять файл удобно локальной копией страницы редактора: подставить `diagram.Restore(json)` и прочитать `document.title` через `chrome --headless --dump-dom`.

**Why:** всё это выяснялось экспериментально (кодировка PS-скриптов, индексы стилей оглавления, формат json редактора), и без записи каждый раз тратится час.

**How to apply:** правки вносить в исходники и пересобирать, а не в .docx; после пересборки обязательно прогонять замеры и обновление оглавления. См. [[nir-polyga-report]], [[doc-pdf-toolchain]].

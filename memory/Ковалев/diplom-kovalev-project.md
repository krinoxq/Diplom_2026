# Диплом Ковалева: организация работы

Пользователь пишет дипломную работу (ВГТУ, кафедра систем информационной безопасности, специальность 10.05.03) по теме «Разработка интеллектуальной системы регулирования рисков безопасности корпоративной системы управления доступом в условиях компрометации учетных записей пользователей».

Рабочая папка — `D:\Диплом`. В `D:\Диплом\Main` складывается итоговый результат (основной файл — `Ковалев Диплом.docx`), там же лежат `Ковалев Матрица целеполагания.xlsx` и `Рекомендации по оформлению.pdf`. Папка `D:\Диплом\Примеры` содержит ВКР прошлых курсов (Герасимова, Косухин, Козина, Харламов, Краснобородкин) — из них пользователь просил брать структуру, стиль и примеры оформления.

Пользователь прямо указал, что вся работа строится на основе матрицы целеполагания: пять её строк (противоречие — постановка задачи — результат на защиту — новизна — практическая ценность — теоретическая ценность) разворачиваются в задачи, результаты и разделы работы.

## Глубина структуры

Пользователь выбрал плоскую структуру разделов — только два уровня нумерации (1, затем 1.1–1.5), и отдельно отметил, что ему нравится вариант, в котором «нет лишних подпунктов подпунктов». Третий уровень нумерации (1.1.1 и глубже) использовать не следует, даже несмотря на то, что в одной из примерных ВКР (Козина) он применён.

## Требования к введению

Файл `Рекомендации по оформлению.pdf` — это статья А.Г. Остапенко и др. «Краткие научно-методические рекомендации по формированию и выполнению технических заданий в области обеспечения информационной безопасности» (Информация и безопасность, 2020, Т. 23, вып. 4). Пользователь просил свериться с ней, и она задаёт обязательный состав введения: актуальность, степень проработанности темы, объект, предмет, противоречия, цель, задачи (сколько противоречий — столько задач), методы исследования, выносимые на защиту результаты, новизна, теоретическая значимость, практическая ценность, апробация, публикация результатов. Первая глава обязана содержать дерево угроз и индуцированных ими рисков, а список литературы — не менее 100 наименований.

## Требование к ИИ-части

Пользователь сказал: «В ии я не шарю, поэтому надо будет использовать упрощенную, но рабочую версию». Модель машинного обучения в работе (выявление аномального накопления полномочий без размеченной выборки) должна быть намеренно простой — такой, которую пользователь сможет объяснить и защитить, и при этом действительно работающей. Не стоит предлагать сложные архитектуры или глубокое обучение; предпочтительны прозрачные алгоритмы вроде изолирующего леса с понятным набором признаков.

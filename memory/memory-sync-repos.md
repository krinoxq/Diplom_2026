Память живёт не только локально в `~/.claude/projects/C--Users-iasti--local-bin/memory/`, но и зеркалится **целиком** в два приватных репо: `C:/github/DevOps-Learning/memory/` и `C:/github/Diplom/Diplom_2026/memory/` (сам `C:/github/Diplom` — не репозиторий, это папка-обёртка). Ветка `main`, remote по SSH, ключ рабочий.

Вся механика — в скрипте `C:/Users/iasti/.local/bin/claude-mem.sh`, ходить в git руками не надо:

- `bash /c/Users/iasti/.local/bin/claude-mem.sh pull` — **перед тем как что-то вспоминать.** Делает fetch по обоим репо, и если с другого устройства прилетели изменения — подтягивает их и обновляет локальные файлы памяти, печатая какие. Если `актуально` в обеих строках — вспоминаю локально, больше ничего не делаю.
- `bash /c/Users/iasti/.local/bin/claude-mem.sh files <раздел> <путь...>` — **после разбора любого учебного файла** (docx, xlsx, pdf, картинки — всё, что открывал и анализировал по диплому/НИР) положить его в `Diplom_2026/materials/<раздел>/` и запушить. Разделы уже заведены: `ВКР-Полыга`, `Примеры-ВКР`, `Корпус-ИБ-201`, `НИР`, `Разное`. Только учебное — личные файлы с рабочего стола туда не идут.
- `bash /c/Users/iasti/.local/bin/claude-mem.sh push "кратко что делали"` — **после любой записи или правки памяти** по темам DevOps и учёба/диплом. Сам подтягивает origin, зеркалит папку, коммитит только `memory/` и пушит в оба репо.

**Why:** нужна общая память между несколькими устройствами, но без того, чтобы каждый «вспомни» съедал кучу токенов на ручные git-команды — одна строка на весь цикл.

**How to apply:**
- Коммит-сообщение по-русски, **не больше 10 слов** (стиль репо: «залил память с основного пк»).
- Скрипт трогает только `memory/` — чужие незакоммиченные правки в DevOps-Learning (`LOG.md`, `ROADMAP.md` и прочее) остаются на месте.
- Если скрипт напечатал `РАЗОБРАТЬ ВРУЧНУЮ` / `PUSH НЕ ПРОШЁЛ` — сказать пользователю, молча не чинить.
- `memory/.gitattributes` в обоих репо держит `*.md text eol=lf`, чтобы CRLF не давал ложных диффов между устройствами.
- На новом устройстве скрипта не будет — пути в нём захардкожены, пересоздать под тамошние пути.
